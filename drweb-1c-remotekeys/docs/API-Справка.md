# Dr.Web — интерфейс автоматизации генерации лицензий (справка по API)

Разбор партнёрского интерфейса Dr.Web, на основе которого построена обработка.
Источник — документ «Интерфейс для автоматизации генерации лицензий» (10 Jul 2006,
обновлён 13 фев 2025) и квик-старт гайд.

> Смежные интерфейсы (НЛ-генерация, продление, цены, выгрузка заказов) —
> в [Доп-интерфейсы.md](Доп-интерфейсы.md). Продукты и скидки — в [Продукты.md](Продукты.md).

> Интерфейс партнёрский и авторизованный: логин/пароль — те же, что для входа на
> партнёрский портал Dr.Web. Не публикуйте учётные данные и серийные номера.

## Общие положения

- Протокол: **HTTPS**.
- Метод: **POST** (предпочтительно) или GET. Некоторые операции отвечают
  `405 Only POST` — обработка всегда использует POST для `f2.drweb.com`.
- В каждом запросе к генерации/блокировке обязательны `login=LOGIN` и `pwd=PWD`
  (логин партнёра вида `avt_NNNNNN`, как на https://pa.drweb.com/).
- Срок лицензии — `period=PERIOD`: `1m`, `3m`, `6m`, `12m`, `24m` и т.д.
- Тип лицензии — `product=ID` (см. [Продукты.md](Продукты.md)).
- Результат — в теле ответа и в HTTP-заголовках/коде состояния.

## Эндпоинты

| Операция | URL | Метод | `act` |
|---|---|---|---|
| Генерация серийных номеров | `https://f2.drweb.com/remotekeys/` | POST | `serial` |
| Блокировка серийного номера | `https://f2.drweb.com/remotekeys/` | POST | `blockserial` |
| Информация по серийному номеру | `https://gsi.drweb.com/register/getserialinfo/` | GET | — |

## 1. Генерация серийных номеров (`act=serial`)

Строка запроса (полный набор параметров):

```
login=LOGIN&pwd=PWD&act=serial&product=ID&period=PERIOD&discount=DISCOUNT
[&order_item_id=STRING][&computers=C][&servers=S][&mailboxes=M][&comment=COMMENTS]
[&traffic=T][&renewserial=XXXX-XXXX-XXXX-XXXX][&testing=yes][&format=xml]
[&for_partner=...][&for_partner_next=...][&supplier=...][&ui_inn=...][&keytype=...]
```

### Количество объектов (зависит от типа продукта)

| Тип (в списке продуктов) | Параметр запроса |
|---|---|
| workstations (рабочие станции), тип `w` | `computers=` |
| servers (серверы), тип `s` | `servers=` |
| mailboxes (почтовые ящики), тип `m` | `mailboxes=` |
| traffic (трафик), тип `t` | `traffic=` |
| users (пользователи), тип `u` | `users=` |

- `traffic` и `mailboxes` **нельзя** передавать одновременно (ошибка `601`).
- Имя параметра `computers` соответствует типу объекта `w` (workstations).

### Прочие параметры

| Параметр | Назначение |
|---|---|
| `discount` | Идентификатор скидки (значения — в прайс-листе). Скидки `1`/`16` означают продление. |
| `order_item_id` | Идемпотентный ключ для перезапроса ранее выданных номеров (коррекция ошибок; хранится несколько дней). |
| `testing=yes` | Тестовый режим: номера не сохраняются. |
| `format=xml` / `format=json` | Формат ответа генерации: XML или JSON (иначе — MIME `multipart/mixed`). |
| `satcodes=yes` | Вернуть коды для продавцов (`satcode`) вместе с серийными номерами. Отдаются только в XML. |
| `renewserial` | Серийный номер, который продлевается. |
| `comment` | Комментарий к заказу. |
| `no_auto_delivery=yes` | Отключает автодоставку продлеваемой лицензии на устройство пользователя (только домашние продукты). |
| `keytype` | В исходном документе не детализирован. |

### Цепочка поставки (по роли партнёра)

| Параметр | Когда | Значение |
|---|---|---|
| `for_partner` | Роль Поставщик/Посредник | Одно из: ИНН, номер карточки Dr.Web, логин партнёра, для которого размещается заказ. |
| `for_partner_next` | Роль Поставщик | Следующее звено после `for_partner` (только вместе с `for_partner`). |
| `supplier` | Роль Дилер/Посредник/Посредник2 при нескольких поставщиках | Логин/ID/ИНН поставщика, через которого размещается заказ. |

> Формат в примере документа: `for_partner=avt_12345|123456789`. По смыслу текста
> `|` разделяет **альтернативные** примеры (логин `avt_12345` **или** ИНН `123456789`),
> то есть передаётся одно значение. Точный формат стоит подтвердить у курирующего
> менеджера Dr.Web.

### Бизнес-анкета пользователя (обязательна для бизнес-продуктов)

| Параметр | Обяз. | Описание | Пример |
|---|---|---|---|
| `ui_cntry` | * (если страна клиента ≠ страны партнёра) | ISO-код страны | `RU` |
| `ui_inn` | * | ИНН клиента | `1928376318` |
| `ui_kpp` | | КПП клиента | `123456789` |
| `ui_orgname` | | Название компании | `ООО "Клиент Dr.Web"` |
| `ui_postindex` | | Почтовый индекс | `109378` |
| `ui_postaddr` | | Почтовый адрес | `Москва, ул. ак. Королёва, д. 20` |
| `ui_www` | | Сайт клиента | `https://www.drweb.ru/` |
| `ui_cname` | | Контактное лицо | `Иванов Пётр Сергеевич` |
| `ui_cjob` | | Должность контактного лица | `Механизатор` |
| `ui_cphone` | | Контактный телефон | `+7 (485) 789-45-87` |
| `ui_cemail` | | Контактный e-mail | `ivanov@example.com` |
| `ui_comment` | | Комментарий по клиенту | `Наш новый клиент` |

При успешной генерации серийные номера возвращаются в теле ответа и дополнительно
отправляются на e-mail, указанный дилером в настройках.

### Формат ответа

По умолчанию — **MIME `multipart/mixed`**: тело содержит часть `text/plain`, в
которой перечислены серийные номера вида `XXXX-XXXX-XXXX-XXXX`. Пример:

```
Content-type: multipart/mixed; boundary="67e70f78ab2797c0265947d64e7a717f";

--67e70f78ab2797c0265947d64e7a717f
Content-Type: text/plain
...
Serial(s) has been generated.
Home products (Dr.Web Security Space)
Workstations: 3
Period: 24m
XXXX-XXXX-XXXX-XXXX
--67e70f78ab2797c0265947d64e7a717f—
```

**`format=xml`** — XML вида `<response>`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<response>
  <info><status>ok</status><comment>…</comment></info>
  <serials>
    <item>4D4D-ED3S-RUAN-VFDU</item>
  </serials>
</response>
```

Серийный номер — в `response.serials.item` (несколько номеров → несколько `item`).
С `satcodes=yes` у каждого `item` появляется атрибут `satcode` (код для продавца):
`<item satcode="ABCD1234">4D4D-ED3S-RUAN-VFDU</item>`. Коды для продавцов отдаются
только в XML.

**`format=json`** — JSON:

```json
{ "status": "ok", "comment": "…", "serial": "1234-5678-ABCD-EFGH" }
```

Обработка разбирает XML (`<response>`, включая `satcode` и `status`) и JSON структурно,
а для MIME / нераспознанного формата извлекает серийные номера из тела скользящим окном
по шаблону `XXXX-XXXX-XXXX-XXXX`.

## 2. Блокировка серийного номера (`act=blockserial`)

```
login=LOGIN&pwd=PWD&act=blockserial&serial=SERIAL[&reason=TEXT]
```

- Блокировать серийный номер можно, **пока по нему не получен ключ**. Если ключ
  уже получен — блокировать нужно сам ключ.
- Успех — `HTTP 200`.

## 3. Информация по серийному номеру (`getserialinfo`)

```
GET https://gsi.drweb.com/register/getserialinfo/?serial=XXXX-XXXX-XXXX-XXXX
```

Ответ — XML `<serialattrs>`. Набор полей может отличаться от запроса к запросу;
обработка разбирает XML толерантно (отсутствующие поля просто не попадают в результат).

| Поле | Значения | Описание |
|---|---|---|
| `period` | `1d`, `1m`, `12m` … | Срок действия лицензии |
| `pid` | целое | Идентификатор продукта (`product`) |
| `dcode` | целое | Идентификатор скидки (`discount`) |
| `pcode` | всегда `UNKNOWN` | — |
| `registered` | yes/no | Зарегистрирован ли серийный номер |
| `fromupdater` | yes/no | Возможна ли регистрация через апдейтер |
| `created` | дата/время | Дата и время создания ключа |
| `expires` | дата/время | Дата и время окончания срока действия ключа |
| `expired` | yes/no | Истёк ли срок |
| `renew` | yes/no | Является ли номер продлением (скидки 1, 16) |
| `renewed` | yes/no | Продлён ли серийный номер |
| `valid` | yes/no | Верен или нет |
| `blocked` | yes/no | Заблокирован или нет |
| `drwebes` | yes/no | Включает ли лицензию на Dr.Web ES |
| `type` | home/corp | Домашний или бизнес-продукт |

## Коды ошибок

Полная таблица — в [КодыОшибок.md](КодыОшибок.md). Ключевая особенность: один и тот
же HTTP-код означает разное в разных операциях (например, `412`, `403`, `401`),
поэтому расшифровка в обработке зависит от действия (`serial`/`blockserial`/`info`).

## Пробелы исходного документа (учтено в обработке)

1. **Продукты и их ID** — известные ID и НЛ-базовые лицензии/компоненты сведены в
   [Продукты.md](Продукты.md). Не хватает плоского референс-списка НЛ и каталога
   кодов продуктов (см. там же).
2. **ID скидок (`discount`)** — получены (`21`, `1`, `8`, `2`, `16`, `14`, `18`),
   см. [Продукты.md](Продукты.md). Допустимые комбинации — в прайс-листе Dr.Web.
3. **Формат `for_partner`/`supplier`** — уточнить у менеджера (см. выше).
4. **`keytype`** — не детализирован; поддержан как дополнительный параметр.
5. ~~Схема XML-ответа генерации~~ — **получена** из квик-старт гайда (см. «Формат ответа»):
   `<response><serials><item satcode="…">SERIAL</item></serials></response>`, а также JSON.
6. **Различие полей `<serialattrs>`** между примером и таблицей — парсер толерантен.

## Форматы ответа генерации (сводно)

| `format` | Тело ответа | Коды продавцов (`satcodes=yes`) |
|---|---|---|
| не задан | MIME `multipart/mixed` | — |
| `xml` | `<response>…<serials><item>…` | атрибут `satcode` у `item` |
| `json` | `{ "status": "...", "serial": "..." }` | не поддерживаются |
