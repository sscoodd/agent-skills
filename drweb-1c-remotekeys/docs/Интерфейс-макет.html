Блокировка серийного номера

Блокировать серийный номер можно, пока по нему не получен ключ. Если ключ уже получен — блокировать нужно сам ключ.

Информация по серийному номеру

Запрос к gsi.drweb.com без авторизации. Возвращает атрибуты лицензии (срок, продукт, скидка, статус, признаки продления и блокировки).

Результат HTTP 200
Генерация серийных номеров
HTTP: 200
Статус: ok
Серийные номера (1):
  4D4D-ED3S-RUAN-VFDU   [satcode: ABCD1234]
----- Тело ответа -----
<response>
  <info><status>ok</status></info>
  <serials>
    <item satcode="ABCD1234">4D4D-ED3S-RUAN-VFDU</item>
  </serials>
</response>

Функционал

Три операции над одной формой. Учётные данные и флаги — общие; операция выбирается вкладкой.

ГенерацияPOST
f2.drweb.com/remotekeys/

act=serial — выдаёт серийные номера по продукту, периоду, скидке и количеству объектов. Серийники — в результате и на e-mail дилера.

БлокировкаPOST
f2.drweb.com/remotekeys/

act=blockserial — блокирует серийный номер с указанием причины. Успех — HTTP 200.

ИнформацияGET
gsi.drweb.com/register/getserialinfo/

Возвращает XML <serialattrs> с атрибутами лицензии. Авторизация не требуется.

Обработка ответа и ошибок

  • Разбор ответа. Структурно разбирает XML (<response><serials><item satcode="…">) и JSON (format=xml / format=json); для MIME multipart/mixed и нераспознанного формата — извлечение серийников скользящим окном по шаблону XXXX-XXXX-XXXX-XXXX. Коды продавцов и статус ok попадают в результат.
  • Коды ошибок — с учётом операции. Один HTTP-код значит разное (например 412, 403, 401), поэтому расшифровка зависит от действия. Плюс кастомные коды 590–634. В результат добавляется фрагмент тела ответа сервера.
  • Сбой соединения. Сеть/таймаут/TLS → код -1 и текст исключения, форма не «падает».
  • Атрибуты. Для «Информации» и XML-ответа поля <serialattrs> выводятся списком; парсер толерантен к отсутствующим полям.

Безопасность и валидация

  • Пароль — режим пароля на поле, передаётся POST-телом (не в query, не в журналах прокси), не выводится в результат и не логируется.
  • Тестовый режим (testing=yes) — для отладки: выданные номера не сохраняются на стороне Dr.Web.
  • Проверки перед отправкой — логин/пароль обязательны везде; продукт и период — для генерации; серийный номер — для блокировки и информации.
  • Сеть — на сервере (управляемое приложение); при работе через прокси задаётся ИнтернетПрокси.

Это макет для согласования интерфейса до сборки в EDT. Поля и таблица соответствуют реквизитам формы 1:1 (см. docs/СборкаОбработки.md). Вкладки — способ подачи; в 1С это либо страницы формы, либо группы. Значения в полях — примеры.
