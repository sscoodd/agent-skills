# Интерфейс и функционал обработки

Описание планируемого интерфейса внешней обработки (этап согласования до сборки в
EDT/Конфигураторе). Наглядный макет — `Интерфейс-макет.html` (открывается в браузере).

Поля и таблица соответствуют реквизитам формы 1:1 (см. [СборкаОбработки.md](СборкаОбработки.md)).
Вкладки — способ подачи; в 1С это либо страницы формы, либо группы.

## Схема формы

```
┌─ Dr.Web: генерация лицензий ───────────────────────────────┐
│ Учётные данные партнёра                                     │
│   Логин*          [__________________]                      │
│   Пароль*         [•••••••••••• (режим пароля)]             │
│   [ ] Тестовый режим (testing=yes)                          │
│   [x] Ответ в XML (format=xml)                              │
│                                                             │
│ ( Генерация )( Блокировка )( Информация )   ← вкладки       │
│ ┌─ Генерация ───────────────────────────────────────────┐  │
│ │ Параметры лицензии:  Продукт*  Период*  Скидка         │  │
│ │ Объекты:  Компьютеры  Серверы  Ящики  Трафик  Пользов. │  │
│ │ Дополнительно:  Комментарий  order_item_id  Продление  │  │
│ │ ┌ Доп. параметры (Имя → Значение) ───────────────────┐ │  │
│ │ │ ui_inn      | 7714533600                            │ │  │
│ │ │ for_partner | avt_12345                             │ │  │
│ │ └────────────────────────────────────────────────────┘ │  │
│ │ [ Сгенерировать ]                                      │  │
│ └────────────────────────────────────────────────────────┘  │
│                                                             │
│ Результат                                    [ HTTP 200 ]   │
│ ┌────────────────────────────────────────────────────────┐  │
│ │ Серийные номера (1):                                    │ │
│ │   XXXX-XXXX-XXXX-XXXX                                    │ │
│ │ ----- Тело ответа -----                                 │ │
│ │ Serial(s) has been generated. ...                       │ │
│ └────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

## Элементы формы

### Общая шапка (для всех операций)

- **Логин**, **Пароль** — учётные данные партнёрского портала. На поле пароля включён
  режим пароля; пароль передаётся только POST-телом.
- **Тестовый режим** — флажок `testing=yes` (выданные номера не сохраняются на стороне Dr.Web).
- **Ответ в XML** — флажок `format=xml` (включён по умолчанию).

### Вкладка «Генерация»

- *Параметры лицензии*: **Продукт**, **Период**, **Скидка**.
- *Защищаемые объекты*: **Компьютеры**, **Серверы**, **Почтовые ящики**, **Трафик**,
  **Пользователи** — по типу продукта. `traffic` и `mailboxes` взаимоисключающи.
- *Дополнительно*: **Комментарий**, **order_item_id**, **Продлить серийный**.
- *Таблица «Дополнительные параметры»* (**Имя → Значение**) — расширяемый механизм для
  бизнес-анкеты (`ui_*`), цепочки поставки (`for_partner`/`for_partner_next`/`supplier`)
  и любого прочего параметра (`keytype` и т.д.) без правки кода.
- Кнопка **Сгенерировать**.

### Вкладка «Блокировка»

- **Серийный номер**, **Причина**. Кнопка **Заблокировать**.
- Блокировать серийный номер можно, пока по нему не получен ключ; иначе блокируют сам ключ.

### Вкладка «Информация»

- **Серийный номер**. Кнопка **Информация по номеру**.
- Запрос к `gsi.drweb.com` без авторизации; возвращает атрибуты лицензии.

### Результат

Текстовая консоль: HTTP-код, распознанные серийные номера, атрибуты (из XML), сырое
тело ответа. Пароль в результат не выводится.

## Функционал

| Операция | Метод · endpoint | Действие |
|---|---|---|
| Генерация | POST · `f2.drweb.com/remotekeys/` | `act=serial` — выдаёт серийники (+ дубль на e-mail дилера) |
| Блокировка | POST · `f2.drweb.com/remotekeys/` | `act=blockserial` — блокирует номер (успех = 200) |
| Информация | GET · `gsi.drweb.com/register/getserialinfo/` | XML-атрибуты лицензии, без авторизации |

### Поля формы → параметры запроса

| Поле формы | Параметр | Назначение |
|---|---|---|
| Логин / Пароль | `login` / `pwd` | Учётные данные; пароль — POST-телом |
| Продукт | `product` | Идентификатор продукта |
| Период | `period` | Срок: `1m`, `12m`, `24m`… |
| Скидка | `discount` | Идентификатор скидки (1/16 — продление) |
| Компьютеры | `computers` | Рабочие станции (тип «w») |
| Серверы · Ящики · Трафик · Пользователи | `servers` · `mailboxes` · `traffic` · `users` | Количество объектов по типу продукта |
| Продлить серийный | `renewserial` | Продлеваемый серийный номер |
| order_item_id | `order_item_id` | Идемпотентный ключ для перезапроса |
| Таблица доп. параметров | `ui_*` · `for_partner` · `supplier` · `keytype` | Бизнес-анкета, цепочка поставки, прочее |

### Обработка ответа и ошибок

- **Разбор ответа** — и MIME `multipart/mixed`, и XML; серийные номера извлекаются
  скользящим окном по шаблону `XXXX-XXXX-XXXX-XXXX` независимо от формата.
- **Коды ошибок — с учётом операции** (один код значит разное: `412`, `403`, `401`)
  плюс кастомные `590–634`; в результат добавляется фрагмент тела ответа.
- **Сбой соединения** (сеть/таймаут/TLS) → код `-1` и текст исключения; форма не падает.
- **Атрибуты** `<serialattrs>` выводятся списком; парсер толерантен к отсутствующим полям.

### Безопасность и валидация

- Пароль — режим пароля, POST-тело, не логируется и не выводится в результат.
- Проверки перед отправкой: логин/пароль — везде; продукт/период — для генерации;
  серийный номер — для блокировки и информации.
- Сетевые вызовы — на сервере (управляемое приложение); прокси — через `ИнтернетПрокси`.
