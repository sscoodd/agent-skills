# Мониторинг свичей ядра

Пакет внедрения: алерты по здоровью в Observium + контроль изменений
конфигураций (Oxidized + syslog-правила). Предпосылка: Observium уже
опрашивает свичи ядра по SNMP — здесь добавляются только алертинг и
слежение за конфигами.

> Каталог `infra/` — внутренний ops-материал этого форка, к каталогу
> скиллов (`skills/`) отношения не имеет и в upstream не предлагается.

## Состав

| Файл | Что внутри |
|---|---|
| `observium/alert-checkers.md` | 10 чекеров здоровья: метрики, условия, задержки, ассоциации |
| `observium/syslog-config-tracking.md` | Приём syslog + правила «конфигурация изменена» с алертом в реальном времени |
| `observium/config.php.snippet.php` | Фрагменты для `config.php`: syslog, почта, вкладка Config |
| `oxidized/docker-compose.yml` | Запуск Oxidized рядом с Observium |
| `oxidized/config` | Конфиг Oxidized: git-история, хуки уведомлений, push во внешний git |
| `oxidized/router.db.example` | Пример списка устройств |
| `oxidized/hooks/notify-diff.sh` | Уведомление с диффом после каждого изменения конфига |
| `switches/device-prep.md` | Что включить на самих свичах (syslog, NTP, учётка для бэкапов) |

## Архитектура

```
                    SNMP (уже настроен)
свичи ядра ────────────────────────────▶ Observium ──▶ алерты здоровья
    │                                        ▲              (почта/Telegram)
    │  syslog (реальное время)               │
    ├───────────────────────────────────────▶┘ syslog-правило ──▶ алерт
    │                                          «конфиг изменён, кем, когда»
    │  SSH (по расписанию)
    └──────────◀── Oxidized ──▶ git-история конфигов ──▶ дифф-уведомление
                                (+ push в центральный git)
```

Два механизма слежения за конфигами дополняют друг друга: syslog даёт
мгновенный сигнал «кто и когда менял», Oxidized — точный дифф «что
именно изменилось» и полную историю в git.

## Порядок внедрения

1. **Свичи** — `switches/device-prep.md`: NTP, syslog на сервер
   Observium, учётка read-only для Oxidized, ACL на доступ с хоста
   мониторинга. ~15 минут на устройство.
2. **Группа устройств** — в Observium создать device group
   `core-switches` и включить в неё свичи ядра. Портам аплинков и
   межкоммутаторных линков проставить description по конвенции
   (`CORE:`, `UPLINK:`, `ISL:`) — на неё опираются ассоциации чекеров.
3. **Чекеры** — `observium/alert-checkers.md`: завести контакты
   (почта/Telegram), затем 10 чекеров по таблице.
4. **Syslog** — `observium/syslog-config-tracking.md`: включить приём
   syslog, добавить правила на сообщения об изменении конфигурации,
   привязать алерт.
5. **Oxidized** — каталог `oxidized/`: развернуть, проверить первый
   снятый конфиг, включить хук уведомлений и push в центральный git
   (рекомендуется приватный репозиторий в вашем Gitea).
6. **Приёмка** — чеклист ниже.

## Чеклист приёмки

Каждый пункт — реальное испытание, не «настроено и забыто». Тесты,
затрагивающие живой трафик, — только в согласованное окно.

- [ ] Ложное падение: закрыть SNMP/ICMP от Observium к одному свичу
      ACL-ом → в течение 2 опросов приходит алерт «device down»,
      после снятия ACL — recovery-уведомление.
- [ ] Порт: увести в down тестовый порт с description `CORE:` →
      алерт за ≤ 2 минуты. Порт без метки алерта давать не должен.
- [ ] Железо: на резервированном БП снять одну линию питания →
      алерт по состоянию PSU (если резерва нет — пропустить).
- [ ] Изменение конфига: поменять description на свободном порту →
      syslog-алерт с именем пользователя приходит за секунды;
      в git Oxidized появляется коммит с диффом ровно этой строки;
      приходит дифф-уведомление.
- [ ] Мониторинг мониторинга: сломать пароль Oxidized на одном
      устройстве → приходит уведомление о неудачном снятии конфига.
- [ ] Перезагрузка (в окно): алерт «device rebooted» после подъёма.

## Эксплуатация

- Плановые работы — через Scheduled Maintenance в Observium
  (глушит алерты по группе на окно), а не отключением чекеров.
- Пороги CPU/памяти/утилизации подобраны консервативно; после
  2–3 недель наблюдения скорректировать по фактическим базовым
  уровням, чтобы алерты не превращались в шум.
- Git-история конфигов — источник правды при разборе инцидентов:
  `git log -p -- <hostname>` показывает всю историю изменений
  устройства.
